# 5. Управление содержанием проекта — ITTO

> ФСП — EEF · АПО — OPA · ИСУП — PMIS. Термины: `glossary.md`.

**Базовый план по содержанию** = описание содержания проекта + ИСР + словарь ИСР (+ пакеты планирования).
**Содержание продукта** измеряется по требованиям; **содержание проекта** — по плану УП.

---

## 5.1 Планирование управления содержанием · Plan Scope Management · Планирование
**Суть:** описать, как содержание будет определяться, валидироваться и контролироваться.

- **Входы:** устав · план УП (план управления качеством, описание ЖЦ проекта, подход к разработке) · ФСП · АПО
- **Инструменты:** экспертная оценка · анализ данных (анализ альтернатив) · совещания
- **Выходы:** **план управления содержанием** · **план управления требованиями**

## 5.2 Сбор требований · Collect Requirements · Планирование
**Суть:** определить, задокументировать и управлять потребностями и требованиями стейкхолдеров.

- **Входы:** устав · план УП (планы управления содержанием, требованиями, вовлечением стейкхолдеров) · документы (журнал допущений, реестр уроков, реестр стейкхолдеров) · бизнес-документы (бизнес-кейс) · соглашения · ФСП · АПО
- **Инструменты:** экспертная оценка · сбор данных (мозговой штурм, интервью, фокус-группы, анкетирование и опросы, бенчмаркинг) · анализ данных (анализ документов) · принятие решений (голосование — единогласие, большинство, относительное большинство; автократическое; многокритериальный анализ) · отображение данных (диаграммы сродства, ментальные карты) · межличностные навыки (**метод номинальных групп**, наблюдение/беседа, фасилитация — JAD, QFD, user stories) · **контекстная диаграмма** · **прототипы** (в т.ч. раскадровка)
- **Выходы:** **документация требований** · **матрица отслеживания требований** (RTM)

⚠️ Классы требований: бизнес, стейкхолдеров, решения (функциональные / нефункциональные), переходные, проектные, требования к качеству. RTM связывает каждое требование с бизнес-целью и результатом.

## 5.3 Определение содержания · Define Scope · Планирование
**Суть:** разработать подробное описание проекта и продукта.

- **Входы:** устав · план УП (план управления содержанием) · документы (журнал допущений, документация требований, реестр рисков) · ФСП · АПО
- **Инструменты:** экспертная оценка · анализ данных (анализ альтернатив) · принятие решений (многокритериальный анализ) · межличностные навыки (фасилитация) · **анализ продукта**
- **Выходы:** **описание содержания проекта** (описание содержания продукта, поставляемые результаты, критерии приёмки, **исключения из проекта**) · обновления документов (журнал допущений, документация требований, RTM, реестр стейкхолдеров)

## 5.4 Создание ИСР · Create WBS · Планирование
**Суть:** декомпозировать поставляемые результаты и работы на более мелкие управляемые компоненты.

- **Входы:** план УП (план управления содержанием) · документы (описание содержания проекта, документация требований) · ФСП · АПО
- **Инструменты:** экспертная оценка · **декомпозиция**
- **Выходы:** **базовый план по содержанию** · обновления документов (журнал допущений, документация требований)

⚠️ Нижний уровень ИСР — **пакет работ** (не операция!). ИСР ориентирована на **результаты**, а не действия. Правило 100%. **Контрольный счёт** (control account) — точка управления выше пакетов работ. Операции появляются только в 6.2.

## 5.5 Подтверждение содержания · Validate Scope · Мониторинг и контроль
**Суть:** формализовать **приёмку** завершённых результатов **заказчиком/спонсором**.

- **Входы:** план УП (планы управления содержанием и требованиями, базовый план по содержанию) · документы (реестр уроков, отчёты о качестве, документация требований, RTM) · **верифицированные поставляемые результаты** (из 8.3) · данные об исполнении работ
- **Инструменты:** **инспекция** · принятие решений (голосование)
- **Выходы:** **принятые поставляемые результаты** · информация об исполнении · запросы на изменение · обновления документов

⚠️ **8.3 Контроль качества** = правильность (верификация, внутри команды) → **5.5** = приёмка (валидация, с заказчиком). Обычно 8.3 выполняется до 5.5.

## 5.6 Контроль содержания · Control Scope · Мониторинг и контроль
**Суть:** отслеживать статус содержания и управлять изменениями базового плана, не допуская **расползания содержания** (scope creep).

- **Входы:** план УП (планы управления содержанием, требованиями, изменениями, конфигурацией; базовый план по содержанию; базовый план исполнения) · документы (реестр уроков, документация требований, RTM) · данные об исполнении · АПО
- **Инструменты:** анализ данных (анализ отклонений, анализ трендов)
- **Выходы:** информация об исполнении · запросы на изменение · обновления плана УП · обновления документов

⚠️ **Scope creep** — неконтролируемое расширение без корректировки сроков/стоимости/ресурсов. **Gold plating** — добавление «от себя» сверх требований; тоже нарушение.
