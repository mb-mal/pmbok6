# 4. Управление интеграцией проекта — ITTO

> ФСП — факторы среды предприятия (EEF) · АПО — активы процессов организации (OPA) · ИСУП — информационная система управления проектами (PMIS). Термины: `glossary.md`. Состав плана и документов: `project-documents.md`.

**Роль области:** РП объединяет все области знаний. Ответственность за интеграцию **не делегируется** — только РП.

---

## 4.1 Разработка устава проекта · Develop Project Charter · Инициация
**Суть:** формально авторизовать проект и дать РП полномочия использовать ресурсы организации. Устав выпускает **спонсор** (инициатор), а не РП.

- **Входы:** 1) Бизнес-документы: бизнес-кейс, план управления выгодами · 2) Соглашения · 3) ФСП · 4) АПО
- **Инструменты:** экспертная оценка · сбор данных (мозговой штурм, фокус-группы, интервью) · межличностные навыки (управление конфликтами, фасилитация, проведение совещаний) · совещания
- **Выходы:** **устав проекта** · **журнал допущений** (assumption log)

⚠️ Бизнес-кейс и план выгод — не документы проекта, а *бизнес-документы*; РП их не пишет, но может рекомендовать изменения. Без устава проект не начат.

## 4.2 Разработка плана управления проектом · Develop Project Management Plan · Планирование
**Суть:** определить, подготовить и скоординировать все компоненты плана в единый интегрированный план.

- **Входы:** устав проекта · выходы других процессов планирования · ФСП · АПО
- **Инструменты:** экспертная оценка · сбор данных (мозговой штурм, контрольные списки, фокус-группы, интервью) · межличностные навыки (управление конфликтами, фасилитация, проведение совещаний) · совещания (в т.ч. **kick-off**)
- **Выходы:** **план управления проектом** (18 компонентов: 10 планов по областям + 4 доп. плана + 3 базовых плана + описание ЖЦ и подхода к разработке — см. `project-documents.md`)

⚠️ После утверждения базовых планов любые их изменения — только через 4.6.

## 4.3 Руководство и управление работами проекта · Direct and Manage Project Work · Исполнение
**Суть:** выполнять работу по плану и внедрять одобренные изменения (корректирующие, предупреждающие действия, исправления дефектов).

- **Входы:** план УП (любой компонент) · документы проекта (журнал изменений, реестр извлечённых уроков, список вех, коммуникации проекта, расписание, матрица отслеживания требований, реестр рисков, отчёт о рисках) · **одобренные запросы на изменение** · ФСП · АПО
- **Инструменты:** экспертная оценка · ИСУП · совещания
- **Выходы:** **поставляемые результаты** · **данные об исполнении работ (WPD)** · **журнал проблем** (issue log) · запросы на изменение · обновления плана УП · обновления документов (список операций, журнал допущений, реестр уроков, документация требований, реестр рисков, реестр стейкхолдеров) · обновления АПО

⚠️ Журнал проблем *создаётся* здесь. Одобренные изменения *реализуются* здесь, а *одобряются* в 4.6.

## 4.4 Управление знаниями проекта · Manage Project Knowledge · Исполнение *(новый в 6-м изд.)*
**Суть:** использовать существующие и создавать новые знания (явные и неявные) для достижения целей и обучения организации.

- **Входы:** план УП (все компоненты) · документы (реестр уроков, назначения команды, иерархическая структура ресурсов, критерии выбора поставщиков, реестр стейкхолдеров) · поставляемые результаты · ФСП · АПО
- **Инструменты:** экспертная оценка · **управление знаниями** (нетворкинг, сообщества практиков, семинары, сторителлинг, шэдоуинг — для неявных знаний) · **управление информацией** (базы уроков, библиотеки — для явных знаний) · межличностные навыки (активное слушание, фасилитация, лидерство, нетворкинг, политическая осведомлённость)
- **Выходы:** **реестр извлечённых уроков** (lessons learned register) · обновления плана УП · обновления АПО

⚠️ Уроки фиксируются **на протяжении всего проекта**, а не только в конце. Неявное знание передаётся через людей, явное — через документы.

## 4.5 Мониторинг и контроль работ проекта · Monitor and Control Project Work · Мониторинг и контроль
**Суть:** отслеживать, анализировать и регулировать прогресс относительно целей исполнения из плана УП; готовить отчёты для стейкхолдеров.

- **Входы:** план УП · документы (журнал допущений, основа оценок, прогнозы стоимости, журнал проблем, реестр уроков, список вех, отчёты о качестве, реестр рисков, отчёт о рисках, прогнозы расписания) · **информация об исполнении работ (WPI)** · соглашения · ФСП · АПО
- **Инструменты:** экспертная оценка · анализ данных (альтернатив, затрат-выгод, **освоенного объёма**, первопричин, трендов, отклонений) · принятие решений (голосование) · совещания
- **Выходы:** **отчёты об исполнении работ (WPR)** · запросы на изменение · обновления плана УП · обновления документов (прогнозы стоимости и расписания, журнал проблем, реестр уроков, реестр рисков)

⚠️ Поток данных: **WPD** (4.3, сырые) → **WPI** (процессы контроля, сравнение с планом) → **WPR** (4.5, отчёты для решений).

## 4.6 Интегрированный контроль изменений · Perform Integrated Change Control · Мониторинг и контроль
**Суть:** рассматривать **все** запросы на изменение, одобрять/отклонять их и управлять изменениями поставляемых результатов, документов и плана.

- **Входы:** план УП (план управления изменениями, план управления конфигурацией, базовые планы по содержанию, расписанию, стоимости) · документы (основа оценок, матрица отслеживания требований, отчёт о рисках) · отчёты об исполнении работ · **запросы на изменение** · ФСП · АПО
- **Инструменты:** экспертная оценка · **инструменты контроля изменений** (управление конфигурацией и изменениями) · анализ данных (альтернатив, затрат-выгод) · принятие решений (голосование, **автократическое**, многокритериальный анализ) · совещания (**совет по контролю изменений, CCB**)
- **Выходы:** **одобренные запросы на изменение** · обновления плана УП · обновления документов (**журнал изменений**)

⚠️ Алгоритм PMI при запросе изменения: 1) оценить влияние на все ограничения → 2) рассмотреть варианты → 3) оформить запрос → 4) решение CCB/спонсора → 5) обновить план и документы → 6) сообщить стейкхолдерам. **Никогда** не вносить изменение без одобрения, даже по просьбе заказчика.

## 4.7 Закрытие проекта или фазы · Close Project or Phase · Закрытие
**Суть:** завершить все операции проекта/фазы/контракта, архивировать информацию, передать результат, высвободить ресурсы.

- **Входы:** устав · план УП · документы (журнал допущений, основа оценок, журнал изменений, журнал проблем, реестр уроков, список вех, коммуникации проекта, измерения контроля качества, отчёты о качестве, документация требований, реестр рисков, отчёт о рисках) · **принятые поставляемые результаты** · бизнес-документы · соглашения · закупочная документация · АПО
- **Инструменты:** экспертная оценка · анализ данных (анализ документов, регрессионный анализ, анализ трендов, анализ отклонений) · совещания
- **Выходы:** обновления документов (реестр уроков) · **передача итогового продукта/услуги/результата** · **итоговый отчёт** · обновления АПО

⚠️ Закрытие закупок в 6-м издании входит сюда (отдельный процесс 12.4 удалён). При досрочном прекращении проекта 4.7 всё равно выполняется. Последний шаг — архивирование и высвобождение ресурсов.
