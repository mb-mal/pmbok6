## Группы процессов — резюме

| Группа | Кол-во | Ключевая цель | Ключевой выход |
|---|---|---|---|
| **Инициация (IP)** | 2 | Авторизовать проект/фазу, определить стейкхолдеров | Устав, реестр стейкхолдеров |
| **Планирование (PL)** | 24 | Определить содержание, цели и план действий | План УП + базовые планы |
| **Исполнение (EX)** | 10 | Выполнить работы по плану | Результаты, WPD |
| **Мониторинг и контроль (MC)** | 12 | Отслеживать, анализировать, корректировать | WPI/WPR, одобренные изменения |
| **Закрытие (CL)** | 1 | Формально завершить проект/фазу | Передача результата, итоговый отчёт |

## Какой процесс запускать — по ситуации

| Ситуация | Процесс(ы) |
|---|---|
| Нужно разрешение начать проект | 4.1 |
| Появился новый стейкхолдер | 13.1 → 13.2 |
| Заказчик просит изменение | 4.6 (оценка → CCB) → 4.3 (реализация) |
| Результат готов, нужно принять | 8.3 (верификация) → 5.5 (приёмка) |
| Отклонение от бюджета/сроков | 7.4 / 6.6 → 4.5 → 4.6 при изменении базового плана |
| Новый риск | 11.2 → 11.3 → 11.5 |
| Риск реализовался | 11.6 (ответ), журнал проблем (4.3) |
| Конфликт в команде | 9.5 |
| Нужен подрядчик | 12.1 → 12.2 → 12.3 |
| Стейкхолдер недоволен информированием | 10.3 → 10.1 (обновить план) |
| Завершение фазы / контракта | 12.3 → 4.7 |
