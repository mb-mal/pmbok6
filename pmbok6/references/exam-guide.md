# Подготовка к PMP на базе PMBOK 6

> ⚠️ Экзамен PMP строится не по PMBOK, а по **Exam Content Outline (ECO)**. В ECO 2021: домены **Люди (42%)**, **Процесс (50%)**, **Бизнес-среда (8%)**, около половины вопросов — agile/гибрид. PMI периодически обновляет ECO (в т.ч. веса доменов) — **перед подготовкой проверь актуальную версию на pmi.org**. PMBOK 6 + Agile Practice Guide остаются лучшим источником по процессам, ITTO и формулам; для agile, людей и бизнес-среды дополняй материалами ECO.

## 1. «Мышление PMI» для ситуационных вопросов
1. **Сначала проанализируй**, потом действуй. Ответы «немедленно сделать X» часто неверны, если нет оценки ситуации.
2. **Не эскалируй сразу** — РП сначала решает в пределах полномочий; эскалация — если вне полномочий или порогов.
3. **Следуй плану**: что говорит план управления (рисками, коммуникациями, изменениями)?
4. **Изменения** — только через 4.6; даже если просит спонсор или заказчик.
5. **Риск реализовался** → выполнить запланированный ответ; не запланирован → обходное решение, затем обновить реестр.
6. **Конфликт** — предпочтительно сотрудничество, в частном порядке, сначала участники сами.
7. **Проактивность**: выявить риски и стейкхолдеров заранее, а не реагировать.
8. **Команда**: в agile — фасилитировать и убирать препятствия, а не раздавать задачи; уважать самоорганизацию.
9. **Этика**: честность в отчётах, раскрытие конфликта интересов, соблюдение законов — всегда.
10. **Уроки** — собирать на протяжении проекта.
11. Вопрос «что сделать **сначала/далее**» — ищи шаг, логически предшествующий остальным.

## 2. Частые ловушки
| Ловушка | Правильно |
|---|---|
| Верификация = валидация | 8.3 проверяет правильность (внутри), 5.5 — приёмка заказчиком |
| Нижний уровень ИСР — операция | Пакет работ; операции — в 6.2 |
| Управленческий резерв входит в базовый план | Нет — только резерв на непредвиденные |
| Устав пишет и утверждает РП | Выпускает спонсор; РП может помогать писать |
| Качество = сорт | Нет; низкое качество — всегда плохо, низкий сорт — допустим |
| Gold plating — хорошо для заказчика | Запрещено |
| σ пути = Σσ | σ пути = √Σσ² |
| SPI < 1 = проект опоздает | Только если отставание на КП |
| Выравнивание не меняет КП | Может сдвинуть КП и финиш; сглаживание — нет |
| Закрытие закупок — отдельный процесс | В 6-м изд. — в 12.3 и 4.7 |
| Реестр рисков создаётся в 11.1 | В 11.2 |
| Журнал проблем создаётся в 4.5 | В 4.3 |
| Эскалация — только для угроз | И для возможностей тоже |
| Fast tracking дешевле crashing и без последствий | Увеличивает риск и переделки |
| Контроль качества делает только QA-отдел | Качество — ответственность всех; за качество продукта отвечает РП |
| Невозвратные затраты учитывают при решении | Не учитываются |

## 4. Мини-тренажёр (формат для агента)
При запросе практики: генерируй вопрос → 4 варианта → жди ответа → объясняй, почему верный вариант верен и **почему каждый неверный неверен**, со ссылкой на процесс/файл. Меняй сложность по результатам. Для расчётных — проверяй через `pmcalc.js`.

### Примеры
1. **EV = 400, AC = 500, PV = 450. Какой статус?** → CPI = 0,8 (перерасход), SPI = 0,89 (отставание).
2. **Ключевой стейкхолдер жалуется, что не получает отчёты. Что сделать сначала?** → Проверить план управления коммуникациями и реестр стейкхолдеров (10.1/13.1), затем обновить план.
3. **Член команды уходит из проекта посреди работ, замены нет. Что сначала?** → Оценить влияние на расписание/риски (анализ), затем вести переговоры с функциональным руководителем.
4. **Заказчик просит добавить мелкую функцию «бесплатно». Что делать?** → Оформить запрос на изменение и провести через 4.6.
5. **Идентифицированный риск реализовался. Что сначала?** → Выполнить запланированный ответ из реестра рисков.
